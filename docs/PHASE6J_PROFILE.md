# Phase 6J — Profile (11 October 2026)

Photo-led personal space now combines an editable preferred name/programme/level, biography/interests, saved visibility/show-programme preferences, private prepared photo and useful activity shortcuts. Profile photos are cropped/compressed locally, stored as bounded owned-image records and survive reload in the demo; display preserves the square portrait crop. Removal is explicit. Email, account ID and role cannot be changed by this form. Demo personalization preserves the current identity and authority; API preferences do not pretend to update university records or publish a public profile.

`ProfilePreferences` and strict bounded schemas extend the source/owner/email-qualified workspace. Profile actions are intent-loaded, single-flight and abort/live-owner guarded. Guests get sign-in rather than private local activity. API mode uses proposed publisher-owned `/workspace/profile` GET and `/workspace/profile/profile` PUT/DELETE; it never falls back to demo preferences or sends authority/email edits. Storage denial is explicitly visit-only. Dialogs preserve failed input, close on successful change and return focus to a connected trigger or named profile heading. Shared owned-photo rendering now accepts an explicit aspect and handles failed blob loading; default listing/report ratios stay unchanged.
